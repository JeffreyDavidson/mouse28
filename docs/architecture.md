# Mouse28 Architecture

## Public application

Public routes are defined in `routes/web.php` and rendered with Blade through the shared `layouts.app` layout. Tailwind, Alpine, and public JavaScript are delivered by the existing Vite entry points.

The homepage is assembled by `HomeController` in this order: hero, featured post, latest posts, optional guides teaser, podcast, and about, followed by the shared footer newsletter. Community Stories are intentionally not part of the application.

## Content boundaries

- `Post` owns blog articles. A post relates to any number of episodes, and an episode to any number of posts, through the `episode_post` pivot table (`Post::episodes()` and `Episode::posts()`, both `BelongsToMany`; TLA's shape: a composite primary key, no timestamps, and a link removed when either side is permanently deleted). Editors pick them in the post form's multiple, searchable "Related Episodes" select. The public post page repeats its episode aside once per published related episode in episode number order (a signed preview shows every related episode that is not trashed), and an episode page lists up to four published related posts. The legacy `posts.episode_id` column was copied into the pivot by a guarded migration and then dropped (with its foreign key) by `drop_legacy_post_link_category_and_author_columns`.
- `Guide` owns durable resources grouped by accessibility, park strategy, food and reviews, or family planning. Guides support source URLs and review dates because park policies can change.
- `Episode` owns podcast installments, Transistor share URLs, distribution links, show notes, and transcripts. A validated Transistor share URL is converted to the provider's single-episode embed URL. Legacy hosted and external audio fields remain readable for compatibility but are no longer part of the editing or listening workflow.
- `Podcast` owns the single show-level metadata record.
- `Category` (`categories`: `name`, unique `slug`, optional `description`; The Laravel Architect's table and model, without its `#[Sluggable]` attribute because that package is not installed yet, so editors type the slug) groups blog posts. A post belongs to at most one category through the nullable, indexed `posts.category_id` (`Post::category()`; deleting a category sets its posts' `category_id` to NULL); `Category::posts()` and `publishedPosts()` read the other way. `category_label` is the category's name (empty when there is none). Administrators manage categories in the "Categories" Filament resource under Content (TLA's form, table and pages) and can also create one inline from the post form's required, searchable category select. A migration created one category per value of the retired `PostCategory` enum (its label as the name, its value as the slug, so `/blog?category=` URLs are unchanged) and linked every post, soft-deleted ones included, by that slug; it refuses to finish while any post's legacy `category` string lacks a `category_id`. The legacy `posts.category` string was dropped by the same migration, together with the `IgnoresLegacyCategoryColumn` trait, so `$post->category` is simply the relation. Guides keep the `GuideCategory` enum.
- Authors: a post or guide credits one or more users through the `post_user` and `guide_user` pivots (`HasAuthors::authors()`, `BelongsToMany` with a `position` column for the byline order; composite primary key, no timestamps, a credit removed when either side is permanently deleted). Only users with `is_author` are offered (the `User::authors()` scope); `users.bio` holds each author's short public bio. Two dedicated, non-admin author users ("Jeffrey Davidson" and "Cassie Davidson", placeholder `.invalid` emails and random unusable passwords, so they cannot sign in or receive mail) were created by a migration, which reuses an existing `is_author` user of the same name but never a same-named admin account, then credited every post and guide, soft-deleted ones included, from the legacy `author` value (`jeffrey`, `cassie`, `both` = Jeffrey then Cassie) and refuses to finish while a record with an `author` has no credit. The byline (`author_name`) is the full name for one author, first names joined with " & " in position order for several, and "Mouse28 Team" for none; `author_initials` derives from it. The post page shows one "about the author" block per author with that author's bio (a general sentence when the bio is empty or there are no authors), and JSON-LD `author` is one `Person` or a list of `Person`s in byline order. Eager-load `authors` wherever a byline renders (blog archive cards and featured story, post page, guide page). The admin forms use the shared `AuthorsSelect` (required, multiple, searchable, every author by default, the chosen order saved as the byline order); `QuickDraft` and `SampleContentSeeder` credit every author. Public archives write `authors` (names in byline order) and import by name onto existing authors only (unknown names are ignored, no users are created), still accepting an older `author` value. The legacy `posts.author` and `guides.author` strings were dropped by `drop_legacy_post_link_category_and_author_columns`, which refuses to run while a row with an `author` has no credit; the `ContentAuthor` enum is retired. Per-site difference: The Laravel Architect keeps a single `posts.user_id` / `author()` relation, so this many-to-many shape is mouse28-only and must stay a site-level difference in the package phase.
- `SocialProfile` (`social_profiles`: `platform` as the `SocialPlatform` enum, optional `label`, https `url`, `is_enabled`, `show_in_footer`, `show_on_contact`, `sort_order`) holds the site's social accounts. Administrators manage them in the "Social Profiles" Filament resource under Settings (create, edit, delete and drag to reorder). `SocialProfilesComposer` shares the enabled footer profiles with the shared layout, which lists them as external links in a "Follow" footer column (hidden when there are none), and `ContactViewModel` adds the enabled contact-page profiles to the Contact page ("Find us on", using each profile's label or its platform name). The scopes `forFooter()` and `forContactPage()` hold the visibility and ordering rules. This adds one query to every public page, which the query-budget tests count. The migration copied the old podcast `instagram_url` and `tiktok_url` values into this table; those columns still exist on `podcasts` (and in the public content archive) until a later migration drops them, but they are no longer edited or shown anywhere.
- `ContactInquiry` stores contact submissions for the admin inbox, with the sender's name, email and message encrypted at rest.

`GuideCategory` is a backed enum cast by Eloquent; its stored strings and archive values remain unchanged. `PublishStatus` (`draft`, `in_review`, `published`, `scheduled`, copied byte-for-byte from The Laravel Architect) is persisted in a `status` column on posts, guides, episodes and newsletter issues; it provides its own `label()`/`color()` rather than Filament's `HasColor` and `HasIcon`, so it stays identical to the shared copy. Posts and guides keep their Markdown text in a nullable `content` longText column (The Laravel Architect's name; its column is NOT NULL). The legacy `body` column was dropped by the `drop_legacy_published_and_body_columns` migration, which refuses to run while any row holds text only in `body` and changes nothing in that case; rolling back to a release before it needs a backup restore. `ContactType` supplies the contact form's choices and labels and is cast on `ContactInquiry.type`; `ContactInquiryStatus` (`new`, `in_progress`, `resolved`) tracks follow-up.

Posts, guides, episodes and newsletter issues use The Laravel Architect's publishing traits, copied byte-for-byte: `#[PublishingStatus]` (`app/Models/Attributes`) names the `status` and `published_at` columns, and `HasPublishingStatus` (with `HasPublicationDate` and `HasPublishingConfiguration`) supplies the `published()`, `scheduled()` and `unpublished()` scopes and the model methods. Each model implements `App\Contracts\Publishable`, which is shared with The Laravel Architect. `isPublished()` means live now: the status is Published or Scheduled and the publish date has arrived, matching the `published` scope, so a scheduled item goes live when its date arrives with no job. `isScheduled()` means a live status with a future date. `publish()` keeps an existing date and otherwise uses now, and saves Scheduled for a future date and Published otherwise. `unpublish()` returns the content to Draft and keeps its date and permalink. In Review is a pre-publication status like Draft (its approval fields arrive with the editorial review slice). The traits' own `publishingIssues()` (which calls The Laravel Architect's `ContentReadiness`, not yet ported) is overridden by each model's `publishingIssues()`. The legacy `is_published` flag was dropped from posts, guides, episodes and newsletter issues by the same migration, which also refuses to run while any published row is still a draft; the status is the only source of truth. Public detail controllers (`abort_unless($model->isPublished(), 404)`), permalink locking and responsive-cover generation use the status, so direct URLs cannot expose drafts, content in review or scheduled content. The shared `PublishContentAction` and `UnpublishContentAction` (`app/Filament/Actions`) are byte-identical to The Laravel Architect's and provide the edit-page publishing controls. Publish appears for content that is neither live nor scheduled, and Unpublish for content that is either. Publishing is refused, with a notification listing the missing details, while the model's `publishingIssues()` is not empty. Admin authorization has no per-model policies: `AdminPanelProvider::boot()` registers `Gate::before(fn (User $user): bool => $user->is_admin)`, which answers every ability (including Filament's resource checks, action `->authorize()` calls, and preview routes) for signed-in users. Capability limits live on the resources instead; for example, `ContactInquiryResource` returns `false` from `canCreate()` and `canEdit()` because inquiries arrive only through the public form.

Posts, guides, and episodes use `HasTagsUntilForceDeleted` (`app/Models/Concerns`, shared with The Laravel Architect) instead of spatie/laravel-tags' `HasTags`. The package detaches tags on every `deleted` event, which also fires for soft deletes, so trashed content would lose its tags before it could be restored. The trait keeps the package's tag behavior but detaches tags only on force delete.

Site search is handled by the invokable `SearchController`. It searches published content independently with length-aware pagination per group (`mouse28.search_results_per_page`, default six) (`postsPage`, `guidesPage`, and `episodesPage`). Links preserve the query and other groups' pages; counts report all matching records. Publication date and ID provide stable ordering. Every query begins with the models' `published` scopes so drafts and scheduled content remain private. Search result pages are marked `noindex,follow` and are not included in the sitemap.

Guides are retained as a dormant feature. `GUIDES_ENABLED` defaults to `false`; while disabled, guide archives and detail routes return 404 responses and guides are omitted from the homepage, shared navigation, search, and sitemap. Filament management and signed preview links remain available so the editorial library can be prepared before the public launch.

`ContentContinuation` keeps detail pages connected without exposing unpublished records. Post recommendations prioritize published posts in the same category (`category_id`) and fill remaining spaces with recent posts; guide recommendations prioritize the current category and fill remaining spaces with recent guides, while episode pages link to the chronologically adjacent published episodes. Episode adjacency and episode/guide archive pagination break publication-date ties by ID. Article and guide category labels link back to their filtered indexes.

Public detail pages emit Schema.org JSON-LD through `StructuredData`: `BlogPosting` for posts, `Article` for guides, `PodcastEpisode` for episodes, and `BreadcrumbList` navigation for each type. JSON output is hex-escaped before it is placed in the document head.

The public layout normalizes canonical and social-image URLs to absolute URLs. Landing pages provide page-specific search and social descriptions. Category archives and paginated archives use self-referencing canonicals, while text searches and alternate sort views are marked `noindex,follow` and canonicalized to the clean archive URL.

## Administration and authorization

Spatie Activitylog records Eloquent create, update, delete, and restore events for posts, guides, and episodes, plus create/update/delete events for podcast settings, under the `editorial` log. Each model declares an explicit attribute allowlist; updates retain only changed values and skip empty changes. The authenticated user is the causer when present; CLI/import operations without an authenticated user have no causer. Podcast contact email, users, credentials, and contact submissions are not logged. Read-only public requests do not write audit records. Bulk query-builder writes and quiet model operations bypass model events and therefore are not audited.

The `activity_log` migration must run before deploying the logging-enabled models. Records are stored server-side; this slice does not add a Filament audit-history viewer or replace the existing recent-content dashboard widget. No automatic log-deletion schedule is enabled. Audit rows may contain draft editorial text and must remain private; they are not a replacement for backups or a tamper-proof audit system.

Filament is mounted at `/admin`. `User::canAccessPanel()` requires the explicit `is_admin` flag. Native authenticator-app MFA is required outside the local environment; local development keeps the same MFA flow available without forcing enrollment. Unenrolled administrators in staging and production must complete setup after password authentication before reaching the panel. Recovery codes are supported. MFA secrets and recovery codes are encrypted and hidden from model serialization by Filament's native concerns. Model policies provide the same boundary for content resources and protected record actions. Custom settings and subscriber pages also enforce administrator access.

`EditorialReadiness` provides shared readiness rules for posts, guides, and episodes; Published or Scheduled content without a publish date is flagged "Set a publish date". The admin tables show the persisted status as a `PublishStatus` badge. Filament list tabs and filters separate drafts (Draft and In Review), scheduled and published content, incomplete records, and review-due material. Each form has a `PublishStatusSelect` (`app/Filament/Forms/Components`, copied from The Laravel Architect) that offers Draft and In Review (episodes: Draft only, via `withoutReview()`); a Published or Scheduled status is shown locked and changes only through the Publish and Unpublish actions. Slug inputs accept lowercase kebab-case. `LocksSlugAfterPublication` (copied from The Laravel Architect) stamps an internal `slug_locked_at` the first time content is saved with a Published or Scheduled status (so scheduling also locks the URL), and the forms disable the slug through `isSlugLocked()`. Editor URLs stay locked after unpublishing or changing publication dates. Legacy past-dated records are conservatively backfilled by the migration; this timestamp is not mass assignable or exported. Explicit canonical imports remain separate from editor URL changes. Post drafts accept empty content, normalized to an empty string; publication still requires content. Editors publish and unpublish from explicit edit-page actions; the form's status select cannot set a live status. Each model's `publishingIssues()` blocks publication only on a short required list: posts need content, an excerpt and a category; episodes need a description and a Transistor episode URL; guides need content, an excerpt, an official source and a review date. The rest of the readiness checklist (artwork, SEO metadata, show notes, duration) is advisory and still appears in the readiness column. A blank publish date is filled automatically, and the edit form refreshes after either action, so a later save cannot write a stale state back. Episode audio and transcripts are tracked as availability information but intentionally do not block publication while the original recordings are unavailable.

Filament global search covers posts, guides, episodes, and contact messages. The dashboard surfaces review-due counts for both sourced posts and guides so time-sensitive information returns to the editorial queue.

`DESIGN.md` defines the shared public and admin visual system. The Filament panel uses a cream workspace with navy navigation and native light-mode controls. Both Vite CSS entry points import the local Besley/Poppins definitions from `resources/css/fonts.css`; the admin uses Filament's `LocalFontProvider` without a font CDN. The panel also loads a small Vite module for accessible searchable selects; it is enabled only on fields that opt into the corrected listbox semantics. Custom dashboard panels share the `filament.dashboard-panel` Blade component, while third-party shell and form styling stays in the registered admin theme.

Content and social artwork uses a 1200:630 aspect ratio. Filament restricts uploads to common web image formats, caps them at 5 MB, and crops and resizes them through its native uploader. The idempotent `content:attach-bundled-artwork` command discovers direct WebP files under `resources/content-artwork/posts`, matches each filename to a post slug, and matches direct episode WebP filenames to episode slugs only when a record does not already have a cover. It writes `featured_image_path` with a query update (no model events, so `updated_at` is unchanged) and then generates the responsive variants for each file it attached, exiting nonzero if any cannot be decoded. Unpublished visual concepts are preserved separately in `resources/content-artwork/concepts` and are never copied or attached by that command.

Production is the source of truth for published editorial content. `PublicContentArchive` exports only published posts, guides, episodes, and public podcast display metadata; its sync mode reconciles posts and guides by slug and episodes by their unique episode number while preserving local drafts and scheduled content. The local-only `content:sync-from-production --isolated=1` command retrieves that archive over SSH, validates the complete persistence payload and every referenced public-storage path before transferring referenced cover, social, and legacy hosted-audio files, and refuses to run in production. Transistor-hosted MP3 files stay outside this sync because the episode share URL is the website's integration point. Version 1 archives now include content-type tag names for each record. Missing tags preserve legacy local associations; an explicit empty list clears them. Archives carry no status field (older archives import unchanged); every imported record is saved with the Published status, and its publish date must already have passed. Post and guide text is written as `content`; archives from before the content column carry it as `body`, which imports still accept (`content` wins when both are present). Cover images are written as `featured_image_path` (posts, guides and episodes) and `cover_image_path` (the podcast); imports and the media transfer still accept an older archive's `cover_image` (the new key wins when both are present), and saving an imported record generates its responsive variants from the transferred original. Each post's category is written as its `category` slug and `category_name`; imports find the local category by slug or create it (the name falls back to the slug's headline for older archives that carry only the slug), a null category clears the post's category, and a record without the key leaves it alone. Each post's published related episodes are written as an `episode_slugs` list in episode number order; imports also accept an older archive's single `episode_slug` (the list wins when both are present) and replace the post's related episodes with the episodes those slugs name. Imports validate dates, enum values, numeric bounds, safe media paths, URLs, duplicate identities, and tag shapes before writing. Users, subscribers, contact submissions, credentials, and environment-specific podcast email remain outside the archive.

Posts, guides, and episodes use Eloquent soft deletion. Deleted content disappears from public queries immediately, while Filament administrators can filter the trash, restore records, or explicitly confirm a permanent deletion. Resource route binding includes trashed records only inside the authorized panel recovery flow.

Each content edit page's Preview action builds a shareable signed link with `App\Support\Content\PreviewUrlGenerator`: `URL::temporarySignedRoute` for `preview.post`, `preview.episode`, or `preview.guide` at `/preview/{type}/{slug}`, expiring after `mouse28.preview_link_hours` (24 by default). The routes sit behind the `signed` middleware, and the signature is the only authorization, so anyone holding an unexpired link can read that draft; unsigned, tampered, and expired links are refused. Changing a draft's slug invalidates links already shared. Preview pages reuse the public templates, carry a visible preview banner, emit `noindex,nofollow` (plus `X-Robots-Tag` and `no-store` headers), and omit structured data.

The migration that introduces `is_admin` promotes existing accounts because every existing account had panel access under the previous behavior. New accounts default to non-administrators.

## External integrations

Newsletter sign-ups are double opt-in and stored in the `subscribers` table. `POST /newsletter` (`newsletter.subscribe`, handled by `NewsletterSubscriptionController`) is protected by a honeypot (`website_url`), Turnstile verification, validation, and an IP rate limit; it always answers "Check your email to confirm your sign-up.", whether or not the address already exists, so it cannot be used to discover subscribers. The admin lists subscribers in the `SubscriberResource` ("Newsletter Subscribers" under Communication; list-only, since readers join through the public form). Each row shows a status derived by `SubscriberStatus::for()` (Active, Pending confirmation, Unsubscribed or Suppressed, as text and colour), and the list can be searched by email, filtered by status, and deleted singly or in bulk. The header and the dashboard "Subscribers" stat count from the database (the stat counts only active readers). Resend only delivers email; it is not read or written for subscriber data (the earlier Resend audience reader and the one-time import command were removed once the database became the source of truth; the import was skipped because the legacy audience was mostly spam sign-ups).

Newsletter issues are written in the `NewsletterIssueResource` ("Newsletter Issues" under Content: list tabs for drafts, scheduled and published issues, a form with title, permalink, excerpt, Markdown content and publish date, and the shared Publish and Unpublish actions; the slug `rss` is reserved for the feed and slugs lock at first publication). Live issues are public at `/newsletter` (a paginated archive, `MOUSE28_NEWSLETTER_ISSUES_PER_PAGE`, each page with its own canonical URL and a 404 past the last page), `/newsletter/{slug}` (Markdown rendered with raw HTML and unsafe links stripped; drafts, scheduled and trashed issues return 404) and `/newsletter/rss` (`GenerateNewsletterRssFeed`, the newest `MOUSE28_NEWSLETTER_FEED_ITEMS`, announced by feed auto-discovery on the archive and issue pages). Editors preview drafts through a signed, expiring `/preview/newsletter/{slug}` link (noindex, with the preview banner) from the edit page or the list's "View on site" action. The archive and live issues are in the sitemap, and the footer links to the archive; the main navigation is unchanged. Sending is separate from publishing. From a live, unsent issue's edit page an administrator can "Send to subscribers" (a confirmation shows the active count; with no active subscribers nothing is sent and the issue stays unsent). `SendNewsletterIssue` runs in one transaction: it creates one `NewsletterDelivery` and queues one `DeliverNewsletterIssue` job on the `database` queue connection for each active subscriber, then sets `sent_at`, so a failure leaves nothing half sent and the unique issue and subscriber pair stops a second send; it also refuses a queue kept in a different database. Each job sends through the `newsletter-delivery` limiter (`MOUSE28_NEWSLETTER_DELIVERY_RATE_LIMIT`, default 5 emails a second), skips deliveries already sent, drops those whose reader is no longer active, retries for up to a day, ends a stuck send after a 60-second timeout (inside the database queue's 90-second `retry_after`, so no second worker picks it up mid-send), and sends a `Resend-Idempotency-Key` built from the app URL, the delivery id and its creation time so a retry cannot double-send and a database reset that reuses an id still gets a fresh key. The editor's test email carries no key, so it can be resent after changing the issue. `NewsletterIssueMail` (HTML and text, Markdown rendered with raw HTML stripped) carries the reader's permanent signed unsubscribe link in the footer and as one-click `List-Unsubscribe` headers; "Send test email" sends the same mail without those headers to every `MAIL_ADMIN_ADDRESS` address and records nothing. The edit page header shows how many deliveries have gone out. `/newsletter` is also the sign-up form's POST address, so `ErrorRecovery` only sends non-GET failures back to the footer form. `NewsletterIssue` (`newsletter_issues`: title, unique slug, excerpt, Markdown content, `status`, `published_at`, `sent_at`, `slug_locked_at`, soft deletes) is a `Publishable` content model using `HasPublishingStatus`, so it goes live through the same rules as posts, guides and episodes (the cover image accessor lives in the `HasFeaturedImage` trait, and SEO fields live in the SEO package's row, which only posts, guides and episodes have) and locks its URL at first publication or scheduling through `LocksSlugAfterPublication`; its only publishing requirement is content. Editorial changes are recorded in the activity log. `NewsletterDelivery` (`newsletter_deliveries`) will record one reader's copy of a sent issue: the unique issue and subscriber pair keeps sends idempotent, and deleting either side removes the row, so no email addresses are copied.

A `Subscriber` model (`subscribers` table: `email`, `subscribed_at`, `verified_at`, `verification_token_hash`, `unsubscribed_at`, `suppressed_at`, `suppression_reason`; the suppression columns are Mouse28-only until ported to The Laravel Architect) exists with a daily `model:prune`. A subscriber is active when confirmed and not unsubscribed; unconfirmed sign-ups are pruned after 7 days and unsubscribed addresses after 30. Suppressed addresses are kept indefinitely so they cannot be mailed again: `SuppressSubscriber::handle($email, SuppressionReason)` (reason `Bounced` or `Complained`) matches the address case-insensitively, sets `unsubscribed_at` if empty plus `suppressed_at` and the reason, clears the token, is idempotent (the first reason and date win) and returns false for an unknown address. A suppressed address is never active, never pruned, and `RequestNewsletterSubscription` does nothing for it, so the sign-up form still shows its usual message but sends no email. `POST /webhooks/resend` (`webhooks.resend`, `ResendWebhookController`) calls it: the route drops the `web` middleware (no session, cookies or forgery token; the Resend signature is the credential) and uses the `resend-webhook` limiter (`MOUSE28_RESEND_WEBHOOK_RATE_LIMIT`, default 60 per minute per IP). The controller verifies the raw body with `Resend\WebhookSignature::verify` (Svix-style HMAC with `RESEND_WEBHOOK_SECRET`, 5-minute tolerance): no secret answers 503, a missing or bad signature 403, a signed body that is not JSON 422, and everything else 204. `HandleResendWebhook::handle()` suppresses every recipient (`data.to`) of `email.bounced` (permanent bounces only; transient ones are ignored), `email.suppressed` (as Bounced) and `email.complained`, and ignores other events and malformed payloads; it returns the number suppressed. Addresses and payloads are never logged, and Telescope ignores `webhooks/*`.

Three Actions manage the subscriber lifecycle, each through `handle()`. `RequestNewsletterSubscription` normalizes the address, takes a per-address cache lock, does nothing for an active subscriber or a pending one inside a 15-minute cooldown, and otherwise stores the SHA-256 hash of a fresh 64-character token, then queues `NewsletterConfirmationMail` with a signed `newsletter.confirm` link that expires after 24 hours (the cooldown is dropped if queueing fails). `ConfirmNewsletterSubscription` marks the subscriber verified and `UnsubscribeFromNewsletter` records the unsubscribe; both clear the token hash. The mail is encrypted in the queue payload and runs on the default queue, so production needs a worker for it. Signed routes expose them. `GET /newsletter/confirm/{subscriber}/{token}` and `GET /newsletter/unsubscribe/{subscriber}` render a noindex page with one button and change nothing, so mail scanners that prefetch links cannot confirm or unsubscribe anyone; the button posts to the confirm route (`newsletter.confirm.store`) or sends `DELETE` to the unsubscribe route (`newsletter.unsubscribe.store`). The confirm routes pass `EnsureValidNewsletterConfirmationLink` instead of the `signed` middleware: it checks the signature and compares the SHA-256 of the URL token with the stored hash, so a link stops working once used. An expired, tampered, unsigned or already-used link, and one whose subscriber was removed (the routes' `missing` handler), all redirect to the footer sign-up form (`/#newsletter`) with one message in the `newsletter` error bag, so the response never reveals whether the subscriber or token exists. `POST /newsletter/unsubscribe/{subscriber}` (`newsletter.unsubscribe.oneClick`) is the RFC 8058 one-click endpoint for mail providers; it is signed and exempt from forgery protection in `bootstrap/app.php`. All of them share the `newsletter-confirm` limiter (`MOUSE28_NEWSLETTER_CONFIRM_RATE_LIMIT`, default 10 per minute per IP), and Telescope ignores `newsletter/*` requests because their paths carry tokens.

Contact submissions follow The Laravel Architect. They use a separate Turnstile action and rate limiter; `StoreContactRequest::toData()` builds a `ContactMessageData` DTO, and `SendContactMessage::handle()` refuses a queue database other than the application's, then creates the `ContactInquiry` and dispatches `SendContactInquiryEmails` with `->beforeCommit()` inside one transaction, so a failed job insert rolls the inquiry back. The job is encrypted (`ShouldBeEncrypted`), carries only the inquiry ID, and runs on the **default** queue of the database connection; it owns locking, sending, delivery timestamps and retries. `SendContactMessageEmails` remains only as a compatibility class: jobs queued or failed on the former `contact-mail` queue forward their ID (IDs were preserved when contact messages were copied into inquiries); remove it once that queue and `failed_jobs` hold none (see `operations.md`). The job retries incomplete delivery up to three attempts, with bounded delays and a 60-second timeout. The non-queued `ContactMessageReceived` and `ContactMessageConfirmation` mailables carry stable, purpose-specific `mouse28-contact-` Resend idempotency keys that protect retries within the provider's 24-hour window; the confirmation goes to a visitor-supplied address, so its subject and body are fixed and never include the inquiry's name, topic or message (the mailable keeps the inquiry out of the view), while the owner notification keeps the submitted content; `ContactInquiry::canRetryEmails()` limits automatic and manual retries to 23 hours after submission, and older queued inquiries fail for manual review. Provider failures are logged without exposing submitted data or provider response bodies. Each successful send is timestamped independently and shown read-only on the inquiry page; authorized administrators can confirm a queued "Retry unsent emails" of only unsent emails within the same window. A per-inquiry cache lock prevents overlapping sends within its 120-second lease. A provider timeout or process failure after acceptance can still make delivery uncertain, so the retry dialog asks the administrator to check the provider first; timestamps are not inbox-delivery receipts. Older messages retain unknown delivery status and are not offered bulk or automatic retries. Because personal fields are encrypted, the admin list cannot search or sort by name or email and the resource is excluded from global search; the encrypted values depend on `APP_KEY` (keep the old key in `APP_PREVIOUS_KEYS` when rotating). Opening a `new` inquiry marks it `in_progress`, and "Mark Resolved" closes it. Unlike The Laravel Architect, inquiries are not prunable: they remain until manually deleted. The public `/privacy` page explains collection, service providers, retention, and how to request help or deletion.

Turnstile tokens are verified by `App\Services\TurnstileVerifier` (shared with The Laravel Architect, plus one guard: the token must be text, so array or numeric tokens fail without a network call). It fails closed when the token, expected action, secret, or verification URL is blank, compares hostnames ignoring case, surrounding spaces, and a trailing dot, and returns `false` on connection failures.

Application Actions live in `app/Actions` and expose a public `handle()` method, matching The Laravel Architect; they are never invokable, and an architecture test enforces it. Examples include `SendContactMessage` and `SendNewsletterIssue`. Filament's own Action classes in `app/Filament/Actions` are separate.

`/robots.txt` is built by `App\Actions\GenerateRobotsTxt` (shared with The Laravel Architect) and served by `RobotsController` outside the `web` middleware group, like a static file: no session cookies, `Cache-Control: max-age=3600, public`, with the global security headers still applied. Cloudflare caches it at the edge and raises the browser `max-age` to four hours (its browser-cache TTL setting), so a change can take about an hour to reach the edge and up to four hours for browsers and crawlers that honor the header. Only the production deployment environment is crawlable (it disallows `/admin`, `/admin/*` and `/preview/` and lists the sitemap); every other environment, including staging, disallows everything. Search results are deliberately not disallowed: they are marked `noindex`, and a crawler must be able to fetch a page to read that tag. The deployment environment is `config('app.deployment_environment')`, set by `MOUSE28_DEPLOYMENT_ENVIRONMENT` (default `production`) and also read by `app:verify-deployment` and the staging Telescope prune schedule.

The contact job declares after-commit dispatch through `ShouldQueueAfterCommit`. Laravel's `WithoutOverlapping` middleware owns the shared `contact-emails:{id}` lock, retaining compatibility with legacy jobs and workers. Contention releases the job for retry after 60 seconds and still consumes an attempt; the lock expires after 120 seconds. Sending must run through the queue middleware, not a direct `handle()` call.

Contact and newsletter submissions use separate named validation bags, and their views only restore old input when feedback belongs to that form. Newsletter return URLs are restricted to the configured application origin, with the homepage footer's `#newsletter` anchor as the fallback.

Unhandled exceptions are registered with the Sentry Laravel integration in `bootstrap/app.php`. Monitoring is opt-in through a production-only DSN; the committed defaults disable tracing, profiling, and default personally identifiable information. `RedactSentryEvent` and `RedactSentryBreadcrumb` (registered on Sentry's `ClientBuilder`) filter sensitive keys, emails, query strings, and token-like path segments before events leave the application. Nightwatch records pass through the `app/Support/Monitoring/Nightwatch` redactors: requests keep only the route path, queries lose literal values, cache keys and user IDs become keyed digests, outgoing requests keep only scheme and host, and exception messages are dropped. Deployments may identify events with `SENTRY_ENVIRONMENT` and `SENTRY_RELEASE` without placing credentials in source control.

The blog RSS feed and sitemap are generated by controllers. Transistor owns the canonical podcast feed configured by `PODCAST_RSS_URL`; public discovery points directly to it, while the legacy `/rss/podcast` route returns a permanent redirect. Reading a feed does not create database records.

Public pages render through anonymous `x-layouts.app` and `x-layouts.error` Blade components. Page views declare their document metadata as layout attributes, and the layout components build a `SEOData` object from those values and render it through the SEO package's `seo()` helper (`ralphjsmit/laravel-seo`, configured in `config/seo.php`: site name, `index,follow` default robots, fallback description and image; the page titles already carry their "| Mouse28" suffix, so the package's title suffix stays off). The layout adds the share-image alt tags and the blog and podcast feed links itself, and pages add head tags such as the hero image preload or the newsletter feed through `@push('head')`. This keeps titles, descriptions, canonical URLs, robots directives, Open Graph data, Twitter cards, and feed discovery out of Blade section inheritance while preserving server-rendered metadata. The package emits one description for search and social cards, so the Open Graph and Twitter descriptions equal the page description.

The blog archive is a class-based Livewire component. Publication-date ties are broken by ID in the selected direction. Initial and interactive metadata share `PostIndexViewModel::metadata`; JavaScript listeners and animation hooks attach to the component and are disposed when it is removed. Search, category, sorting, and pagination update the archive in place (the category filter accepts the slug of any existing category and falls back to every story otherwise; the topic chips list, in creation order and by name, only categories with published posts), preserve the reader's scroll position, and remain synchronized with browser-history query parameters so filtered views can be linked and revisited. The server-rendered links and forms remain usable without JavaScript. The existing Vite entry point loads Livewire and its bundled Alpine runtime only for the blog archive; other public pages retain the smaller standalone Alpine bundle.

`PodcastComposer` supplies show-level metadata to the shared public layout component, while episode ViewModels supply it to episode content views. The homepage receives its shared podcast links from the layout composer. Apple Podcasts, Spotify, and YouTube links configured in Podcast Settings are the public source of truth and are omitted when unavailable. Episode-specific destinations override show-level links on episode pages. RSS always points to the configured Transistor feed. These read paths share a request-scoped `Podcast::info()` result and never create a settings row.

Guide freshness is controlled by `GUIDE_REVIEW_INTERVAL_DAYS`, with a 180-day default. Missing or older review dates are surfaced to editors and produce a public verification notice because accessibility and park-operation details can change. Post source freshness is controlled by `POST_REVIEW_INTERVAL_DAYS` (also 180 days); both intervals live in `config/content.php`, shared with The Laravel Architect. `Post::sourceReviewStatus()` and `Guide::sourceReviewStatus()` return the shared `App\Enums\SourceReviewStatus` (`NotTracked`, `Current`, `ReviewDue`), which supplies the badge label and color in the Filament tables. A post with no official source is `NotTracked`; a guide is always tracked, so it is only ever `Current` or `ReviewDue`.

## Frontend and accessibility

The public layout provides a semantic header, primary navigation, skip link, main landmark, footer, visible focus styles, responsive controls, and reduced-motion behavior. Mobile interactive targets should remain at least 48 pixels. User-authored Markdown is rendered with embedded HTML stripped and unsafe links disabled.

All main public pages share the full footer previously used on About and Contact, including Home, the blog archive and articles, and the podcast archive and episodes. Its single newsletter form owns the `#newsletter` anchor; page bodies do not repeat the signup form. Existing bot protections, validation, and submission feedback remain shared.

The About opening groups the headline and introduction on the left and the existing uncropped 4:3 safari photograph on the right at desktop widths. Mobile stacks the text before the photograph. The page retains its copy, search metadata, and lower editorial content.

HTTP 404, 419, 500, and 503 responses use branded recovery pages. Their lightweight standalone layout avoids session, database, and shared-view dependencies so failures remain renderable. Error pages are `noindex,nofollow`, omit canonical URLs, and never render exception messages. Shared recovery destinations use safe GET routes for contact, newsletter, and admin forms; unknown non-GET requests return to the homepage rather than replaying submissions. Article table-of-contents links update the fragment and focus the destination heading while honoring reduced motion. Unknown routes and unpublished content receive the same 404 response so private titles are not disclosed.

Global response middleware adds `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and a restrictive camera, geolocation, and microphone `Permissions-Policy` to public, admin, feed, and error responses. It also sets `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy` to `same-origin`, adds `Strict-Transport-Security` on HTTPS responses (matching The Laravel Architect's shared contract, even though the production edge also sends it), and declares a content security policy. Public pages use a per-request Vite nonce: inline scripts and `@livewireScriptConfig` carry it, Alpine and Livewire load their CSP builds (`@alpinejs/csp`, `livewire.csp.esm`), and components are registered with `Alpine.data()` so directives are plain property or method references. Only Turnstile, Fathom, and Transistor embeds are allowed as third parties. The Filament admin keeps `unsafe-inline` and `unsafe-eval` for its scripts. Exception responses receive the same headers through `withExceptions(...)->respond(...)`.

The framework health endpoint at `/up` also checks the database: a `DiagnosingHealth` listener in `AppServiceProvider` queries the `migrations` table, so an unreachable database returns `500` with `{"status":"down"}`. When `RUNTIME_HEALTH_ENABLED=true`, it also requires scheduler and queue heartbeats newer than `RUNTIME_HEALTH_MAX_AGE` seconds; an every-minute scheduled task records the scheduler heartbeat and dispatches `RecordQueueHeartbeat` to the default queue. The `app:verify-deployment` command validates required production and staging configuration without printing secret values, including Nightwatch for production and Telescope for staging; `app:verify-production` remains an alias for existing deployment scripts. Administrator email configuration supports comma-separated recipients and validates each address. The independently configured public contact email is also validated. Staging Telescope excludes entire contact/newsletter batches and redacts contact fields and flashed old input elsewhere; its staging-only daily prune retains 48 hours by default through `TELESCOPE_RETENTION_HOURS`. Forge must invoke the application's scheduler. Contact-message retention remains manual.

`AppServiceProvider` enables Laravel's `DB::prohibitDestructiveCommands()` in production. This blocks `db:wipe`, `migrate:fresh`, `migrate:refresh`, `migrate:reset`, and `migrate:rollback`, including forced invocations. Normal forward migrations remain available. The guard follows `APP_ENV`, so Forge staging with `APP_ENV=production` is protected too; it is not a blanket prohibition on custom content commands.

Admin, preview, and error responses also emit `X-Robots-Tag: noindex, nofollow` and `Cache-Control: no-store, private`, preventing crawlers and shared caches from retaining private or failure-specific content. The dynamic and static robots policies both disallow admin pages, authorized previews, and generated search results; the application still uses page-level robots metadata for filtered archives and other contextual indexing decisions.

Pest's Agent, Faker, Livewire, PHPStan, Rector, and Type Coverage plugins are development dependencies. PHPStan's extension installer registers the Pest extension automatically. This is type-declaration coverage, not runtime test coverage or proof of complete type safety. The command uses the same 2 GB memory allowance as static analysis because the local 128 MB default is insufficient. ### Public-page performance benchmark

The runner exits unsuccessfully for navigation errors, unexpected document statuses, uncaught JavaScript errors, or first-party Image/Script/Stylesheet/Font HTTP responses of 400 or higher. The dormant `/guides` document may return 404, but its assets receive no exemption. Reports include per-sample `failureReasons` and summary `failedRuns`; medians still include completed samples, so inspect failures before comparing speed. Third-party console messages remain diagnostic. Network failures without an HTTP response and image decode failures are not covered by this HTTP-asset check.

Navigation reports retain the original TTFB and add DNS, connection setup (including TLS), TLS, pre-request, response-wait, and document-transfer durations in milliseconds, plus an allowlisted set of raw navigation timestamps. TLS is a subset of connection time; DNS and connection time are subsets of pre-request time, not additional totals. Pre-request plus response-wait equals TTFB for these navigation entries. Response-wait includes network latency and is **not** isolated PHP or database execution time. Zero connection phases can indicate connection reuse. Summary rows include median pre-request, response-wait, and document-transfer times; independently calculated medians need not add up. Run `node --test tests/Browser/navigation-timings.test.mjs` to verify the calculations without starting a browser.

Run `npm run benchmark:pages -- --base https://mouse28.test --profile slow-mobile --runs 3 --output /tmp/mouse28-mobile.json` against a built, content-populated local site. Run the same command with `--profile desktop` separately. Select a staging or production origin explicitly; the command never deploys or submits forms. It visits the public landing pages, searches for “disney”, checks the dormant guides route, and discovers one published detail page per enabled content type. `--paths /blog,/episodes` narrows a repeat run; never silently compare runs that discovered different content. When both `CLOUDFLARE_ACCESS_CLIENT_ID` and `CLOUDFLARE_ACCESS_CLIENT_SECRET` are set, the runner attaches them only to requests for the selected origin; it never applies those headers to third-party requests. Do not use staging credentials for arbitrary origins.

The `Staging performance benchmark` GitHub Actions workflow runs this profile against staging each Tuesday at 10:00 UTC and can also be started manually. Configure the `CLOUDFLARE_ACCESS_CLIENT_ID` and `CLOUDFLARE_ACCESS_CLIENT_SECRET` Actions secrets with a dedicated Cloudflare Access service token, and add that token to a Service Auth policy limited to the staging application. The workflow performs three slow-mobile runs and saves the full report as a 90-day Actions artifact, including when the benchmark fails after writing its report. Its `staging-current` revision value labels the target environment; it is not a deployed Git SHA. Record the actual deployed revision from Forge before attributing a change or comparing a specific release. The schedule runs from the repository's default branch, as required by GitHub Actions, so it becomes active after the workflow reaches that branch; manual dispatch can run an additional check between scheduled runs.

Each repeat uses a new browser context for a cold load, then revisits the same URL with its browser cache intact. Cold means **browser** cold, not a flushed server/CDN cache. Slow-mobile conditions are 390×844, DPR 2, 4× CPU slowdown, 150 ms added latency, 200,000 bytes/sec down and 93,750 up. Desktop is 1440×1000/DPR 1 without throttling. Measurements cover a fixed ten-second window after DOMContentLoaded rather than waiting indefinitely for third-party network idleness. The runner reports LCP, FCP, TTFB, session-window CLS, long-task blocking time, observed request/transfer totals, first-party cache headers, incomplete visible images, and error origins. Its blocking-time sum is not Lighthouse TBT, and it does not measure field INP. CDP transfer totals can exclude out-of-process third-party iframe traffic. A null load time or incomplete visible image means the sample did not settle within the window.

Keep browser version, hardware, content, build, viewport, network conditions and origin constant for before/after comparisons. Use three runs and review medians and outliers; do not run browser benchmarks concurrently with builds/tests or other benchmarks. Local Herd and production differ in latency, compression, monitoring and third-party configuration: their timings are not a controlled before/after result. Reports omit cookies, response bodies, console text and third-party URL query strings. Store raw reports as review artifacts, not committed logs.

### Stored media and responsive images

**SEO.** Posts, episodes and guides use the SEO package's `HasSEO` trait: each has one `seo` row (`seo` table, polymorphic `model_type` / `model_id`, with `title`, `description`, `author`, `robots`, `canonical_url`, `image`) that the Filament form edits through the package's `SEO::make()` section (collapsed, title, author, description and robots). The model creates an empty row when it is created and `$post->seo` is never null. Public pages read the row directly (`$post->seo?->title ?: $post->title`, the description falling back to the excerpt or episode description, robots falling back to `index,follow`), and `StructuredData` and `EditorialReadiness` read the same row; the package's `getDynamicSEOData()` is deliberately not defined because it would override saved values. `ScopesMissingSeo` supplies the `missingSeo()` scope behind the admin's "Missing SEO" filter and the needs-attention queue, and the admin tables eager-load `seo` for the readiness badge. The custom share-image upload is retired (the package's field has none; the share image is the cover). The legacy `meta_title`, `meta_description` and `og_image` columns were copied into the rows by `backfill_seo_from_meta_columns` (guarded, re-runnable, never overwriting a saved value) and then dropped by `drop_legacy_meta_columns`, which refuses to run while a title or description has no value in its SEO row or while any `og_image` would be lost, and changes nothing in that case. Public archives keep their `meta_title` / `meta_description` keys, mapped to the row, and no longer carry `og_image`.

Posts, episodes and guides store their cover in `featured_image_path` and the podcast in `cover_image_path` (The Laravel Architect's columns, paths on the `public` disk). The legacy `cover_image` columns were copied into them by the stored media migration, which refuses to finish while any row has a `cover_image` but no new path; the `drop_legacy_cover_image_columns` migration then dropped them (it too refuses to run while a row holds an image only in `cover_image`, and changes nothing in that case). Rolling back to a release before it is not possible without restoring a backup. `HasFeaturedImage` provides `featured_image_url` (the public disk URL) and `ManagesStoredMedia` deletes a replaced original after the database commit and the original on force delete (soft deletes keep files); both are copied byte-for-byte from TLA. The single-row `Podcast` has no soft deletes, so `PodcastObserver` removes its replaced original itself.

Responsive variants are written beside each original as `{directory}/responsive/{filename}-{width}.webp` (WebP quality 82) for the widths in `config/media.php` (`media.responsive_widths`: 480, 640, 768, 1280; TLA's default is 640 and 1280), skipping widths wider than the original. `ResponsiveImageVariants` (copied from TLA unchanged) scales posts, guides and the podcast cover; the mouse28-only `SquareResponsiveImageVariants` subclass makes centered square crops for episodes, whose covers show in square frames, and verifies them against the original's shorter side. The model observers (`PostObserver`, `EpisodeObserver`, `GuideObserver`, `PodcastObserver`, registered with `#[ObservedBy]`) call `ResponsiveImageLifecycle` to generate variants when a record is created or its path changes, and to delete the previous variants after commit; a failed generation logs a warning naming the command to rerun and never blocks saving. Image work happens on save and in commands, never while rendering a page. The commands `posts:`, `episodes:`, `guides:` and `podcasts:generate-image-variants`, `media:repair-responsive-images` (`ResponsiveImageRepairWorkflow`, every type, then verification) and `media:verify-responsive-images` share `ResponsiveImageWorkflow`; see `docs/operations.md`.

The post artwork component, guide artwork component, episode detail hero and podcast archive hero call `srcset()`, which lists only the variants that exist (storage existence checks, no queries) and never the original; without variants the original stays the `src`. Post and episode `sizes` are unchanged; guide artwork uses `sizes="auto, 100vw"` when lazy and `100vw` when eager. The archive's featured cover is eager/high priority; below-fold cards remain lazy. Episode heroes retain high priority and explicit sizing for their square frame. The podcast archive keeps its bundled responsive candidates for the default show artwork and lists the uploaded cover's variants otherwise.

Home's compact podcast panel offers the bundled `public/images/podcast/mouse28-cover-640.webp` alongside the original 1200-pixel WebP. The podcast archive's eager show artwork offers 640- and 768-pixel candidates plus the original. These proportional GD resizes use WebP quality 82; regenerate them alongside any replacement of the bundled artwork. The homepage's native `sizes="auto, 264px"` and archive's explicit frame size let the browser select an appropriate resolution. These bundled files deploy with the repository and do not require the uploaded-artwork generation command. Uploaded show-level artwork and social-image URLs remain unchanged.

Lazy cards use native `sizes="auto"` with a responsive fallback list so the browser can select a candidate using the actual rendered card width; eager heroes use explicit sizes. This follows the [HTML responsive-image sizing rules](https://html.spec.whatwg.org/multipage/images.html#sizes-attributes). The full PHP suite has an explicit test-only 512 MB process budget; it does not change application or production PHP limits.

Generate variants after local public-content sync and after publishing/replacing covers. Post and episode edit pages offer an explicitly confirmed, update-authorized action targeting the saved published record through `--id`; it preserves originals and reports generation failures. Production generation uses Laravel's `ConfirmableTrait`: it requires affirmative interactive confirmation or an explicit `--force`, and noninteractive execution without force cancels. Operational approval is still required before running it on production; until then, the new markup safely serves originals. Derived files are additive and are not automatically pruned. Immutable edge caching is enabled for fingerprinted builds and versioned responsive images; see the Nginx security-header inheritance requirement in `docs/operations.md`. Uploaded show-level artwork and privacy-reviewed field metrics remain follow-up opportunities; do not introduce whole-page shared caching without separating CSRF/session/form-feedback state and publication invalidation.
